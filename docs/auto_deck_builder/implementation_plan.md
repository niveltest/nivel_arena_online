# 自動デッキ構築機能の実装計画

## 概要
ユーザーが選択したリーダーに対して、相性（属性）やデッキ構築ルールを満たしたデッキを自動生成する機能を追加します。
DeckBuilder画面に「自動構築（オススメ）」ボタンを配置し、クリック時にアルゴリズムに基づいてデッキを完成させます。

## 追加するロジック（デッキ生成ルール）
以下の制約を満たすようにカードをプールから選出します。
1. **リーダーの属性に合致するカードのみ**（または無属性）。
2. **デッキ枚数はちょうど40枚**。
3. **同名カードは最大3枚まで**。
4. **トリガーカード（`ON_DAMAGE_TRIGGER`）は最大8枚まで**。

**選出アルゴリズムのアイデア（コストカーブとバランス）**
完全にランダムではなく、ある程度のコストカーブ（低いコストから高いコストへ）とカードタイプ（ユニット、スペル、アイテム）のバランスを考慮して選出します。
- ターゲット構成例：
  - ユニット：約20〜25枚
  - スペル/アイテム：残り
  - トリガー：最大8枚（優先的に採用して防御力を最低限担保）
  - コストカーブ：低コスト(1-3)を多め、高コスト(6+)を少なめにしたピラミッド型〜ベル型

## 変更予定のファイル

### [MODIFY] `components/DeckBuilder.tsx`
- **UI追加**: リーダー選択エリアの近辺、もしくはデッキ操作ボタン群に「自動構築」ボタンを追加。
- **ハンドラ追加**: `handleAutoBuild` 関数を追加し、現在のリーダーを元に上記のロジックで利用可能なカードプール（`allCards`）からデッキを生成し、`setDeck` で状態を更新します。
- **リーダー未選択時の警告**: リーダーが選択されていない場合はアラートを表示。
- **カード不足時のフォールバック**: 所持カード（または実装済みカード一覧）のプールで40枚に満たない場合は、可能な限り追加しアラートを出すか、生成不可としてエラー表示します。

## 検証計画
### 手動検証
1. DeckBuilder画面を開き、任意のリーダーを選択する。
2. 「自動構築」ボタンをクリックする。
3. デッキが40枚埋まるか確認する。
4. 「同名3枚まで」「トリガー8枚まで」「属性一致」のエラーが出ずにサーバー保存できる状態になるか確認する。
5. 複数の異なるリーダーで試し、それぞれ属性が合致したカードのみ採用されているか確認する。
